# 视频代码与文档远程检查点

本次保存四个视频仓库的项目运行入口、采集器、定向测试、环境配置、排障文档和小型报告/身份清单，并保留远程已有的 AgentX 收尾与状态工具更新。这是版本备份，不是新实验批准。

## 远程包含什么

- 共享 CPU、内存、I/O 采样、流式落盘、质量判定和内容摘要代码。
- video-use、OpenStoryline、ViMax、VideoWeaver 的项目脚本及小型配置、测试和记录。
- 原生仓库副本仍按既有策略不提交；OpenStoryline 和 VideoWeaver 的文本适配差异保存在 [补丁清单](../env/video/publication-patches/manifest.json)，绑定各自上游 commit，可在对应干净源码根目录执行 `git apply --check <补丁绝对路径>` 后恢复差异。video-use 当前 source 副本与上游没有文本差异，其项目 overlay 在独立目录保存。
- 当前目标、成果、排障入口及整理后的文档。

## 仅保存在本机的内容

原始数据、视频/图片/音频、模型权重、下载的 CLI/安装包、venv、容器镜像、完整请求/rollout/采样、原始工作区、修改前快照和 `local_archive/` 不进入本次提交。历史清单中的路径与哈希保持原义；远程保留定位信息不表示已上传所有被引用文件。

这意味着远程 checkout 可查阅和恢复代码，但直接运行部分测试/构建仍需本机证据 fixture、按清单准备的上游源码和已登记依赖。尤其 audit 测试使用的历史成片仍是本机 fixture，不为了通过测试重新付费生成。

## 验证口径

在提交前检查候选文件大小、禁止的载荷类型和凭据模式；源码补丁执行只读 `git apply --check`。状态合并保留两侧的命名记录、证据哈希和执行授权边界。缺失的本机证据另列，不删掉历史登记或伪造完整验证。

video-use/OpenStoryline 核心剪辑、ViMax 真实生成与拼接已有记录；VideoWeaver 真实生成和自主拼接为分阶段证据，修复后完整连续生成仍未实测。122 项采集离线回归不等于四条链均完成新口径真实验证。
