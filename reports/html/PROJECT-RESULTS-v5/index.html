综合报告原有证据矩阵 · 六个原始 RQ

更新于 2026-10-11；综合v2保持原报告时点口径；新采集批另列卡片和详情，不回写旧结论。本地资源已覆盖 Coding 与 Office 的有限 scope，不等于单工具特性或函数热点已完成。

研究问题当前覆盖允许的结论仍缺什么
RQ1：Agent workload 与传统 LLM workload 有什么不同？形态描述初步覆盖；受控传统 LLM 对照缺失描述各来源中的多轮、上下文、工具交错与状态形态，分别注明原始 trace、模板和静态源码层。没有统一传统 LLM 对照；来源、任务与 harness 差异不能解释为架构因果效应。
RQ2：Agent 时间到底花在哪里？Coding 区间与 DocOps 阶段级部分覆盖限定观测范围内的区间/阶段描述与同任务重复变异；mixed 保留，不按比例分摊。DocOps 缺可靠逐请求/逐工具起止时间；LLM、Agent、Tool、Environment、Sandbox 尚未全部闭合为时间分解；不推算思考或等待时间。
RQ3：真正造成 CPU / Memory / IO 压力的是什么？Coding 与 Office 的 scope 级资源描述已覆盖一部分固定任务配置的容器级资源分布及活动共现；未解决但测量有效的运行也可分析其路径开销。未控制跨类别任务/模型/harness/资源限制混杂；blkio 不是完整文件系统 I/O；共享容器观察不证明单工具独占资源或压力原因。
RQ4：不同 Tool 的 CPU workload 特征是什么？工具结构与 scope 共现已有；工具级特性未闭合描述接口与活动组成、筛选测量候选；不能仅由调用数判定 CPU 特性。缺逐工具/进程级资源边界与线程、调度和基础 CPU 统计；不能认定 compute/memory/IO/latency-bound 或单/多线程。
RQ5：主要热点和软件优化机会在哪里？未闭合；没有有效真实 Agent 函数热点样本指出需要进一步观测的区间，不声称已找到函数热点或优化收益。CPU-02 普通用户检查被拒；特权方案未安装、未批准且安全闭环未完成，路线暂停；不能据此断言特权 perf 必然不可用。
RQ6：多个 Agent 并发时系统会发生什么？受控并发实验缺失描述保存的 subagent/request 形态；不把它当真实调度并发或本机争用测量。缺受控 Agent 并发度对照、资源争用、尾延迟与 sandbox 可扩展性证据。
