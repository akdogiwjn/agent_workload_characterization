## 结构怎样得到并核验

选择第二步固定样本中的两个完整会话：

- 单子代理 `bbdcb12440a7ab3496b9fac8b5f9824b1672`，21 条请求、1 个显式组、2 条执行链。
- 多子代理 `2a2da059b7425d9dc1f999fca1177bc1cdb9`，30 条请求、6 个显式组；官方加载器另识别 1 条辅助链，加父链共 8 条执行链。

首先使用同一个已安装的官方 `agentx-harness==1.0.7`，按第二步固定配置离线重建元数据，未启动 benchmark 服务或发送模型请求。保留所有链的原生来源索引，然后将官方 `post-SPAWN`、链内顺序、`SPAWN_JOIN` 编译成依赖图，检查无环、无缺节点、51 个来源请求与第二步实际抓取一一对应。固定请求正文仍取自第二步已核验的官方回放器抓包，不使用离线重新生成的文本作为新输入。

新增依赖边共 50 条：41 条链内顺序、8 条子链启动、1 条辅助链汇合。每条边都核验 `后继请求开始 >= 前驱响应结束`，见 [dependency_audit.csv](dependency_audit.csv)。单子代理样本在此元数据中，父链最后一条请求结束后才启动子链，所以 HTTP 峰值并发为 1。多子代理先经过父链与辅助链的汇合，再启动 6 条并行子链。

本轮最大在途请求数限制为 8，实测达到 6；不是把会话的全部请求同时发出。遇到失败会停止发新请求并等待已发请求结束，本轮未触发失败策略。运行前的 5 项结构/调度测试通过；最终共 46 项离线测试通过，包括并发、等待所有子链、失败后排空、半开区间计数等反例检查。

保留的是**官方加载器生成的分支依赖关系**，原始时间等待被移除。`ignore_trace_delays` 下没有保留基于原始 API 区间的额外跨链前沿约束，也没有复刻原生请求的持续时间或完整重叠比例。原始 `t/api_time` 的并发统计与本次实际 HTTP 并发分开保存。

## 输出负载的缺口

多子代理 8 条请求正常提前 `stop`；其中几个最大的原始输出未被当前模型生成出来。例如：

| 原生指针 | 原始输出长度 / 本次上限 | 实际输出 | 结束原因 |
| --- | ---: | ---: | --- |
| `/requests/6/requests/4` | 59,903 | 1,246 | stop |
| `/requests/8/requests/2` | 59,725 | 825 | stop |
| `/requests/10/requests/3` | 52,108 | 360 | stop |
| `/requests/7/requests/2` | 16,721 | 729 | stop |

这些是有效 API 响应，没有记为失败，也没有补发请求、追加提示词或拼接生成来凑长度。本轮反映的是“固定合成输入、当前远程模型实际生成”的资源需求。要研究原始长输出负载，需要另建能够明确控制生成长度的实验模式，确认服务是否支持最小生成长度或忽略 EOS 等机制；不能只增大会话数就声称补齐这个缺口。本报告不把它标成已解决。

所有新返回内容只用于采集，不反馈进下一条固定输入。业务工具没有执行，原始业务成功率没有评价；非思考模式固定，未出现 reasoning 内容。计数以 DeepSeek usage 为准，不用第二步 Qwen 分词器冒充远程精确 token 计数。缓存命中数是服务端报告值，未测量 GPU、显存或其他服务端资源，未做关闭缓存的对照。
