## 怎样回放和测量

来源为第二步已验证的五会话中的最小单执行链完整会话，20 条原始请求全部保留。使用第二步官方 `agentx-harness==1.0.7` 实际发出的冻结请求内容，以独立轻量 HTTP 客户端发送；没有再次运行原业务 Agent。每条 `messages` 的哈希、原生请求索引和完整请求正文均逐条核验。只替换模型为 `deepseek-flash`，把 `max_completion_tokens` 改成接口文档支持的 `max_tokens`，保留各请求原始输出目标，并显式设置 `thinking=disabled`、`temperature=0`、SSE 及 usage 返回。

官方当前模型文档列出 `deepseek-flash` 对应 DeepSeek-V4.1-Flash-1017，支持 1M 上下文；本次响应只报告别名 `deepseek-flash`，未取得可独立固定的服务端权重身份。思考模式默认开启，所以显式关闭；本次 21 条响应都未出现 reasoning 内容。依据：[模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)、[思考配置](https://api-docs.deepseek.com/guides/thinking_mode/)、[Chat Completion 接口](https://api-docs.deepseek.com/api/create-chat-completion/)。

本次保持第二步合成文本，不在请求之间拼接新模型生成结果。输入历史是官方回放器已经构造的固定历史。原始时间间隔未回放，各请求依次执行、并发为 1；原始该会话存在的请求区间重叠没有复现。本轮没有子代理样本、重复试验或关闭缓存的对照组。

采样父进程只监控自己启动的 HTTP 工作进程，未纳入视频会话或整机计数。配置为每轮采样后等待 0.2 秒，实际间隔约 0.25 秒（精确中位数和最大间隔见机器摘要），全尝试共 217 个样点，其中正式会话 212 个。CPU 按一逻辑核 100% 计算；RSS 峰值是采样峰值，可能遗漏更短的瞬时峰值。没有使用整机网络计数，避免并发会话流量混入。

## 可以得出的结论及限制

1. **远程 DeepSeek 连接和固定请求回放可行。** 20 条原始请求的内容保持一致，实际收到 20 份有效流式响应。探针只输出 `OK`，不混入会话统计。
2. **跨分词器会改变实际输入规模。** 原始长度、第二步 Qwen 模板计数和本次 DeepSeek usage 分别保存。单请求相对原始输入偏差为 −1,351～+14 token；不把本次实验描述成对原始 token 数的严格重现，也没有使用 Qwen 分词器核定 DeepSeek 实际输出 token 数。
3. **有直接的缓存字段观察。** 93.799% 来自服务端返回的输入 token 统计。它不等于第一步基于 hash 的历史共享潜力，也不能证明缓存带来多少加速；本次没有无缓存对照和服务端内部观测。首请求缓存为 0 也不能证明账号或服务全局缓存已清空。
4. **客户端负载在此实现下较轻。** 约 40 MiB 的 HTTP 客户端 RSS 包含冻结正文解压、请求序列化和 SSE 抓取；未包含在线合成、真实业务工具、浏览器、子代理进程或模型资源，不能推广成完整 Agent 的内存需求。
5. **这是一个会话的一次试点。** P95 由 20 个请求计算，请求之间的上下文、输出上限与缓存情况不同，不作普遍模型性能排名或因果判断。真实模型可能提前停止，实际输出和目标上限必须同时保留。SSE 包可能含多个 token，不报告伪造的逐 token ITL/TPOT。

下一项可扩展为：显式子代理完整会话与长上下文会话，分别冻结实验配置、保留实际 token 和资源结果；需单独呈现，避免混入本轮单链基线。
